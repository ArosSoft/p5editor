# План разработки

## Опция: Хранилище изображений на Cloudinary

### Логика работы опции:

1. У каждого пользователя p5editor есть свой личный аккаунт Cloudinary, привязанный к его почте (той же, что в профиле p5editor).
2. Если аккаунт Cloudinary ещё не привязан, на странице «Мои изображения» показывается простая пошаговая инструкция по регистрации и кнопка-ссылка на форму регистрации Cloudinary.
3. После регистрации и привязки аккаунта изображения пользователя из Cloudinary отображаются на отдельной странице сайта p5editor.
4. На странице есть кнопка «Добавить изображение» и список загруженных изображений: имя, размер, предпросмотр.
5. Список можно просматривать в разных режимах (сетка карточек / таблица) и открывать карточку изображения для деталей.
6. Дизайн — минималистичный, понятный школьникам: крупные кнопки, простые слова, дружелюбные сообщения об ошибках.

---

## 1. Ключевое архитектурное решение

**Аккаунт Cloudinary — личный, у каждого пользователя свой.** Сайт работает по принципу «подключи свой аккаунт»:

- школьник бесплатно регистрирует аккаунт на cloudinary.com (бесплатный тариф ~25 кредитов/мес);
- на странице «Мои изображения» вводит три значения из консоли Cloudinary: **Cloud name**, **API Key**, **API Secret**;
- после этого сайт загружает картинки в этот аккаунт и показывает их списком.

**Почему так:** не нужно оплачивать хранилище на всех пользователей сайта, у каждого школьника свой лимит, и данные лежат в его собственном аккаунте.

### Ограничение безопасности (важно)

API Secret нельзя хранить и использовать в браузере — любой сможет его украсть. Поэтому:

- секрет хранится в Supabase **зашифрованным** и **никогда не возвращается на клиент**;
- все операции с Cloudinary Admin API (список картинок, удаление, подписанная загрузка) идут через **Supabase Edge Function (прокси)**, которая проверяет JWT пользователя, берёт его секрет из БД и подписывает запросы к Cloudinary;
- напрямую из браузера вызывается только доставка самих картинок (публичные URL вида `res.cloudinary.com/<cloud_name>/image/...`) — это безопасно.

```
Браузер ──(JWT)──► Edge Function cloudinary-proxy ──(подпись API Key+Secret)──► Cloudinary API
   ▲                                                                           │
   └──────────── публичные URL картинок (res.cloudinary.com/...) ◄─────────────┘
```

## 2. Этапы разработки (по уровням)

### Уровень 1: Модель данных и привязка аккаунта
- **Таблица** `cloudinary_accounts` (см. схему ниже) + RLS-политики.
- **Шифрование секрета**: pgcrypto + ключ в секретах Edge Function (или Supabase Vault).
- **Edge Function** `cloudinary-proxy`, эндпоинт `verify` — проверка введённых данных через Cloudinary `/usage`.
- **Frontend**: маршрут `/images` (только для авторизованных) и экран «Привязка аккаунта»:
  - дружелюбная пошаговая инструкция регистрации (пронумерованные шаги);
  - большая кнопка-ссылка «Зарегистрироваться в Cloudinary» → `https://console.cloudinary.com/users/register_free`;
  - форма: Cloud name, API Key, API Secret с подсказками, где каждое значение взять в консоли Cloudinary;
  - кнопка «Проверить и подключить».
- **Типы**: обновить `src/types/supabase.ts` (Database → новая таблица).

### Уровень 2: Страница «Мои изображения» — просмотр
- **Edge Function** эндпоинт `list` — получение списка ресурсов Cloudinary из папки `p5editor/` (пагинация по 24 картинки).
- **Composable** `src/composables/useImages.ts` (по образцу `useStorage.ts`): загрузка списка, состояния `loading/error`, перезапрос.
- **Страница** `src/views/ImagesPage.vue`:
  - состояния: загрузка → пусто («Здесь пока нет картинок») → список → ошибка (с понятным текстом);
  - карточка изображения: предпросмотр (трансформация Cloudinary `w_300` — маленькая и быстрая), имя, размер в КБ/МБ, формат (PNG/JPG…), дата загрузки;
  - переключатель режимов просмотра: **сетка** / **таблица** («с разных ракурсов»);
  - клик по карточке → модальное окно с деталями: большой предпросмотр, имя, размер, размеры в пикселях, кнопка «Скопировать ссылку».
- **Навигация**: пункт «Мои изображения» рядом с «Мои программы» (только для авторизованных).

### Уровень 3: Загрузка новых изображений
- **Кнопка «Добавить изображение»** (большая, зелёная — акцентный цвет сайта) + зона перетаскивания (drag & drop).
- **Проверка на клиенте до отправки**: форматы PNG / JPG / GIF / WebP; размер до 10 МБ; понятные сообщения («Это не картинка», «Файл больше 10 МБ»).
- **Edge Function** эндпоинт `upload` — подписанная загрузка в папку `p5editor/` аккаунта пользователя, уникальный public_id вида `p5editor/<uuid>`.
- **UX**: индикатор прогресса, временная карточка «загружается…», обновление списка после успеха.

### Уровень 4: Управление изображениями
- **Удаление** картинки (кнопка в карточке/модалке + подтверждение «Точно удалить?»).
- **Переименование** (необязательно, отложенно).
- **Отвязка аккаунта** Cloudinary (кнопка в настройках страницы, с подтверждением; зашифрованный секрет удаляется из БД).

### Уровень 5: Интеграция с редактором p5 (необязательно, будущий этап)
- Кнопка «Вставить в скетч» в модалке картинки: копирует готовую строку `loadImage('...')` или вставляет URL в редактор.
- Панель «Мои изображения» прямо в редакторе для быстрого выбора картинки.

## 3. Схема базы данных

### Таблица `cloudinary_accounts`
```sql
create table public.cloudinary_accounts (
  user_id uuid primary key references public.profiles(id) on delete cascade,
  cloud_name text not null,
  api_key text not null,
  api_secret_encrypted text not null,        -- зашифрован pgcrypto, клиенту не отдаётся
  cloudinary_email text,                     -- почта аккаунта Cloudinary (для отображения)
  verified boolean not null default false,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

alter table public.cloudinary_accounts enable row level security;

-- Пользователь видит свою привязку (БЕЗ секрета — см. view ниже)
create policy "own account select"
  on public.cloudinary_accounts for select
  using (auth.uid() = user_id);

create policy "own account update"
  on public.cloudinary_accounts for update
  using (auth.uid() = user_id);

create policy "own account delete"
  on public.cloudinary_accounts for delete
  using (auth.uid() = user_id);
```

Дополнительно — view без секрета для клиента:
```sql
create view public.cloudinary_accounts_safe as
  select user_id, cloud_name, api_key, cloudinary_email, verified, created_at, updated_at
  from public.cloudinary_accounts;
```
(Секрет читает только Edge Function через service role; в RLS-insert запись создаёт также Edge Function от имени пользователя, либо добавляется insert-политика с `with check (auth.uid() = user_id)`.)

Шифрование: `encode(pgp_sym_encrypt(api_secret, current_setting('app.enc_key')), 'base64')`; ключ `app.enc_key` живёт в секрете Edge Function и выставляется через `set_config` в её же транзакции.

## 4. Edge Functions (`supabase/functions/cloudinary-proxy/`)

Общий каркас: все эндпоинты проверяют `Authorization: Bearer <JWT>`, берут `user_id` из токена, загружают credentials из БД (service role), при отсутствии отвечают `account_not_linked`.

| Эндпоинт | Метод | Назначение |
| --- | --- | --- |
| `verify` | POST | Проверить cloud_name/api_key/api_secret через `GET /usage` (до сохранения или после) |
| `link` | POST | Сохранить (зашифровать) credentials пользователя |
| `list` | POST | Список ресурсов: `GET /resources/byFolder p5editor/`, пагинация, поля: public_id, url, bytes, format, width, height, created_at |
| `upload` | POST | Подписанная загрузка файла (multipart) в папку `p5editor/` |
| `delete` | POST | Удаление по public_id (с проверкой префикса `p5editor/`) |
| `unlink` | POST | Удалить привязку из БД |

Технические детали:
- подпись запросов к Cloudinary Admin API — sha1 от параметров + api_secret (или пакет `cloudinary` / простейший fetch);
- CORS для домена сайта; лимиты: не более N запросов в минуту на пользователя (простая защита);
- все ответы — короткие, дружелюбные тексты ошибок на русском (код + сообщение), чтобы страница показывала их школьнику как есть.

## 5. Frontend: маршрут и структура

```
src/views/ImagesPage.vue          — страница «Мои изображения» (все состояния)
src/composables/useImages.ts      — связь с Edge Function, кэш списка
src/components/images/
  CloudinaryOnboarding.vue        — инструкция по регистрации + форма привязки
  ImageCard.vue                   — карточка (предпросмотр, имя, размер)
  ImageGrid.vue / ImageTable.vue  — два режима просмотра
  ImageDetailsModal.vue           — детали + копирование ссылки + удаление
  UploadImageModal.vue            — выбор файла / drag&drop + прогресс
src/router/index.ts               — /images, meta: { requiresAuth: true }
src/types/supabase.ts             — типы новой таблицы
```

### Состояния страницы
1. **Не авторизован** → редирект на главную (уже работает через `requiresAuth`).
2. **Аккаунт не привязан** → онбординг: инструкция + ссылка на регистрацию + форма.
3. **Загружается** → спиннер.
4. **Пусто** → «Здесь пока нет картинок. Нажми “Добавить изображение”» + большая кнопка.
5. **Список** → сетка/таблица карточек.
6. **Ошибка** → человеческое объяснение + кнопка «Повторить».

## 6. Дизайн для школьников (минимализм)

- Крупные кнопки (высота ≥ 48px), один акцентный цвет сайта `#42b883`, тёмная тема как у всего сайта.
- Простые слова: «картинка», а не «ресурс»; «размер файла», а не «bytes».
- Инструкция по регистрации — нумерованные шаги 1-2-3-4 с картинками-скриншотами консоли Cloudinary (заготовить 3–4 скриншота).
- Подсказки прямо в форме: «Cloud name найдёшь в правом верхнем углу консоли Cloudinary».
- Дружелюбные ошибки: «Не получилось подключиться. Проверь, что скопировал ключ целиком, и попробуй ещё раз».
- Пустые состояния с простой иллюстрацией и подсказкой, что делать дальше.
- Все действия обратимы или с подтверждением (удаление — «Точно удалить? Отменить будет нельзя»).
- Размер файла показывать как «1.2 МБ», дату — «3 дня назад».

## 7. Безопасность — чек-лист

- [ ] API Secret никогда не возвращается клиентом и не попадает в localStorage.
- [ ] Секрет зашифрован в БД (pgcrypto/Vault); расшифровка только внутри Edge Function.
- [ ] RLS: строка привязки доступна только владельцу.
- [ ] Edge Function проверяет JWT на каждый запрос.
- [ ] Удаление разрешено только для префикса `p5editor/` (нельзя удалить чужие папки в своём же аккаунте — защита от случайностей).
- [ ] Валидация файлов на клиенте и в Edge Function (тип, размер ≤ 10 МБ).
- [ ] CORS ограничен доменом сайта.
- [ ] Логи Edge Function не содержат секрет.

## 8. Лимиты бесплатного тарифа Cloudinary (для справки школьникам)

- ~25 кредитов в месяц: 1 кредит ≈ 1 ГБ хранилища или 1 ГБ трафика или 1000 трансформаций.
- На странице можно показывать маленький счётчик «использовано места» из `GET /usage` (эндпоинт уже нужен для `verify`).
- При исчерпании лимита Cloudinary отвечает ошибкой — страница обязана показать понятное сообщение.

## 9. Тестирование (чек-лист приёмки)

1. Новый пользователь без привязки видит инструкцию и ссылку на регистрацию.
2. Регистрация в Cloudinary → ввод трёх значений → «Проверить и подключить» → успех.
3. Неверный API Secret → понятная ошибка, данные не сохраняются.
4. Добавление PNG 3 МБ через кнопку и через drag&drop → карточка появляется.
5. Файл 15 МБ / файл .txt → отклоняются с понятным сообщением.
6. Список: имя, размер, предпросмотр корректны; переключение сетка/таблица работает.
7. Модалка деталей: копирование ссылки — ссылка открывается в новой вкладке.
8. Удаление: подтверждение → картинка исчезает из списка и из Cloudinary.
9. Отвязка аккаунта → страница снова показывает онбординг; повторная привязка работает.
10. Проверить, что в DevTools браузера нигде не виден API Secret.
11. Обновление страницы (F5) — список загружается без потери состояния авторизации.
12. Проверка на медленном соединении (3G) — таймауты и сообщения, как в остальном сайте.
