# План разработки

## Этап: Создание и развитие сообществ

### Логика работы сообщества:

1. Участники могут делиться своими скетчами в сообществе, если они к нему принадлежат.
2. Модератор сообщества может подтверждать или отклонять публикацию скетча.
3. По умолчанию скетч публикуется в личном кабинете пользователя и получает уникальную ссылку.
4. Добавить скетч в сообщество можно с помощью этой ссылки.
5. Модератор сообщества может удалять пользователей из списка сообщества в случае нарушения ими правил.
6. Пользователи могут добавляться в сообщество на странице сообщества.
7. Название, назначение и Правила сообщества описаны на его странице.

## 1. Этапы разработки (по уровням)

### Уровень 1: Базовая инфраструктура сообществ
- **Backend API**: CRUD для сообществ (создание, просмотр, редактирование, удаление)
- **Frontend**: Страницы сообществ (список, карточка, создание/редактирование)
- **Безопасность**: RLS политики для сообществ и их участников
- **Навигация**: Меню "Сообщества" в шапке сайта

### Уровень 2: Управление контентом
- **Публикация скетчей**: Связь скетчей с сообществом (sketch_community_id)
- **Модерация**: Система запросов на публикацию (community_submissions)
- **Статусы**: `pending` → `approved`/`rejected` для сообщений в сообществ
- **Уведомления**: Модератору о новых заявках

### Уровень 3: Социальные функции
- **Комментарии к сообщениям**: В тредах, как в Scratch
- **Система лайков/любоф**: Для сообщений сообщества
- **Подписки**: На сообщества и участников
- **Активность**: Лента последних действий в сообществе

### Уровень 4: Продвинутая модерация
- **Жалобы**: На скетчи и комментарии
- **Журнал действий**: Moderation logs для сообществ
- **Тайм-ауты**: Временное ограничение доступа
- **Авто-модерация**: Фильтры запрещённых слов

### Уровень 5: Gamification & стимулы
- **Значки**: За активность в сообществе
- **Рейтинг участников**: Leaderboard по вкладу
- **Курсы**: Групповые обучающие программы
- **События**: Челленджи и конкурсы

## 2. Схемы базы данных

### Таблица `communities`
```sql
- id (uuid, PK)
- name (text) — название сообщества
- slug (text, unique) — URL-часть для сообщества
- description (text) — описание назначения
- rules (text) — правила сообщества (markdown)
- avatar_url (text) — логотип сообщества
- banner_url (text) — баннер сообщества
- creator_id (uuid, FK → profiles.id)
- is_public (boolean) — публичное/частное
- member_count (integer, default: 0)
- created_at, updated_at
```

### Таблица `community_members`
```sql
- id (uuid, PK)
- community_id (uuid, FK → communities.id)
- user_id (uuid, FK → profiles.id)
- role (text) — 'member', 'moderator', 'admin'
- joined_at (timestamp)
- UNIQUE(community_id, user_id)
```

### Таблица `community_invitations`
```sql
- id (uuid, PK)
- community_id (uuid, FK → communities.id)
- invited_by (uuid, FK → profiles.id)
- invite_code (text, unique) — для приглашений по ссылке
- expires_at (timestamp)
- max_uses (integer)
```

### Таблица `community_submissions`
```sql
- id (uuid, PK)
- community_id (uuid, FK → communities.id)
- sketch_id (uuid, FK → sketches.id)
- status (text) — 'pending', 'approved', 'rejected'
- moderator_id (uuid, FK → profiles.id)
- rejection_reason (text)
- created_at, updated_at
```

## 3. Прогрессивные идеи для стимулирования творчества

### 3.1 Коллективные холсты (Collaborative Canvas)
- **Идея**: Скетч, который может одновременно редактировать до 10 человек
- **Технология**: WebSockets + CRDT для конфликт-free редактирования
- **Механика**: Каждый участник видит курсоры других, история правок с именами
- **Применение**: Групповые проекты, коллективные анимации

### 3.2 "Форк-цепочки" (Fork Chains)
- **Идея**: Как git-форки, но для скетчей — каждый форк сохраняет связь с оригиналом
- **Визуализация**: Дерево форков на странице скетча
- **Награды**: За "исторический форк" (100+ наследников) и "визионерский форк" (форкнувший ранние версии)

### 3.3 Творческие лаборатории (Creative Labs)
- **Идея**: Временные закрытые сообщества с темой (1-4 недели)
- **Формат**: 
  - Неделя 1: "Признаки живой природы" — животные
  - Неделя 2: "Абстракция" — геометрия и формы
  - Неделя 3: "Интерактив" — мышь/клавиатура
  - Неделя 4: "Финальный проект" — свободная тема
- **Итог**: Лучшие работы попадают в постоянные галереи

### 3.4 "Мозговые штурмы" (Idea Sprints)
- **Идея**: За 24 часа создать скетч по единой концепции
- **Функции**:
  - Стартовый шаблон кода (скелет)
  - AI-подсказки в реальном времени
  - "Сейв-чекпоинты" каждые 2 часа
  - Голосование за лучшие решения
- **Награды**: Разные категории (самый креативный, самый оптимальный, самый странный)

### 3.5 Менторская программа
- **Идея**: Опытные участники становятся наставниками
- **Система**: Наставник получает "менторские очки" за помощь (решённые вопросы, улучшенные скетчи)
- **Прогресс**: Наставник подтверждает достижения ученика, выдавая значки

### 3.6 "Живые коллекции" (Living Collections)
- **Идея**: Сообщество поддерживает тематическую коллекцию
- **Функция**: Автоматическое добавление одобренных скетчей
- **Музей**: Интерактивная выставка с фильтрами и сортировкой

### 3.7 Кросс-дисциплинарные челленджи
- **Идея**: Совместные челленджи с другими платформами
- - Музыканты → визуалка под трек
  - Поэты → анимация стихов
  - Математики → визуализация формул
- **API**: Экспорт/импорт данных для внешних платформ

## 4. Технические детали реализации

### API Endpoints
```
GET    /api/communities           — список публичных сообществ
POST   /api/communities           — создать сообщество
GET    /api/communities/:slug     — данные сообщества
PUT    /api/communities/:id       — обновить (только модераторы)
POST   /api/communities/:slug/join — присоединиться/по запросу

GET    /api/communities/:slug/submissions — заявки на публикацию
POST   /api/communities/:slug/submissions — отправить скетч на проверку
PUT    /api/submissions/:id       — модерация (approve/reject)

GET    /api/communities/:slug/members — список участников
DELETE /api/communities/:slug/members/:userId — исключить (модератор)

GET    /api/users/:id/communities   — сообщества пользователя
GET    /api/sketches/:id/forks     — форки скетча
```

### RLS Политики (пример)
```sql
-- Публичные сообщества видимы всем
-- Члены частных видят их содержимое
-- Только модераторы могут одобрять заявки
-- Создатель — владелец (admin)
```

### Frontend Routes
- `/communities` — каталог сообществ
- `/communities/:slug` — страница сообщества
- `/communities/:slug/submissions` — заявки (только модераторы)
- `/communities/create` — создание сообщества
- `/labs` — активные лаборатории
- `/challenges` — текущие челленджи
